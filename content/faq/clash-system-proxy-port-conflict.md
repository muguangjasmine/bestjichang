在 Windows 或 macOS 系统上启动代理软件时，最常见的一类弹窗报错莫过于“Port 7890 already in use（端口7890已被占用）”或“Mixed port conflict”。7890 是 Clash 系列内核公认的默认本地监听端口，一旦遭遇端口争抢，内核程序便会因无法绑定套接字而拒绝启动，导致整机断网。遇到这一经典系统级冲突，究竟该如何优雅排查并彻底解决？

## 一、端口冲突的幕后黑手：常见软件与残留僵尸进程

在操作系统中，同一个网络端口在同一时间只能被单一进程独占监听。导致 7890 端口被占用的元凶通常有两大类：第一类是 Clash 自身的历史僵死进程，当客户端非正常关闭、崩溃或系统强制休眠唤醒后，底层的 core 核心进程并未正常释放，依然顽固霸占着该端口；第二类是电脑上同时安装了其他科学上网工具（如 v2rayN、老版 CFW）、部分网络加速器或下载软件，其默认本地代理端口刚好也设为了 7890。

## 二、快速自愈第一招：任务管理器强杀残留僵尸进程

遇到端口报错，最立竿见影的动作是彻底清理残留。在 Windows 下按下 Ctrl+Shift+Esc 打开任务管理器，切换到“详细信息”选项卡，按名称排序寻找是否存在名为 clash.exe、clash-meta.exe、mihomo.exe 或 clash-core.exe 的活动进程。如果发现其踪影，果断点击右下角“结束任务”将其彻底终止。随后重新启动 Clash Verge Rev，绝大多数由于非正常退出引起的端口报错即可当场消除。

## 三、一劳永逸第二招：在客户端中自定义修改监听端口

若清理进程后报错依然顽固出现，说明有其他未知系统服务正在占用 7890。此时最省心、最彻底的解决方案是将 Clash 的监听端口改到一个极难发生冲突的偏门端口号。在 Clash Verge Rev 的“设置（Settings）”中找到“混合端口（Mixed Port）”，将默认的 7890 手动修改为 7895、10808 或 27890，点击回车确认并重启代理服务。内核在新的空白端口上能瞬间顺利绑定，彻底告别冲突纠缠。

## 常见疑问解答

### 如果我把 Clash 混合端口从 7890 改为了 7895，浏览器和系统需要额外修改设置吗？

只要您在 Clash 中开启了“系统代理（System Proxy）”，客户端会自动把 Windows 系统底层的代理注册表端口同步修改为 7895，浏览器和常规软件无需任何手动改动，完全自动适配。

### 如何在 Windows 命令行（CMD）中快速查出具体是哪一个软件占用了 7890 端口？

以管理员身份打开 CMD，输入命令 netstat -ano | findstr :7890 回车，最右侧显示的一串数字即为占用进程的 PID；再输入 tasklist | findstr 对应PID 回车，即可查出该软件的具体可执行文件名。

## 总结与选购自检建议

端口冲突是桌面网络运维中最常见的微小波澜。掌握僵尸进程清理与端口自定义改写两大硬核技能，任何端口占用的阻碍都能在几十秒内烟消云散。
