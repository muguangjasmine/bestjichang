尽管当今绝大多数现代客户端都支持一键点击导入或直接解析订阅链接，但在某些特殊应用场景下——例如在老款智能电视盒子、工业级旧版梅林路由器固件、特定 Linux 无图形化服务器、或是极少数小众开源嵌入式设备上，软件可能仅提供一个空白的手动配置表单或只支持导入原始的 config.json 配置文件。学会看懂并手动组装 Shadowsocks 核心参数，是打通一切老旧设备的硬核基本功。

## 一、看懂 Shadowsocks 节点的四大核心物理元数据

不论配置界面多么简陋复杂，任何一条合法的 Shadowsocks 节点在底层都绝对由且仅由以下四个核心字段唯一定义：第一，Server（服务器地址）：服务商提供的节点连接域名或公网出口 IP；第二，Server Port（远程端口）：通常在 10000 至 65535 之间的一个数字；第三，Password（连接密码）：一串经过高强度加密生成的随机字符凭证；第四，Method（加密算法）：如前文所述的 chacha20-ietf-poly1305 或 aes-256-gcm。

## 二、从标准 ss:// 分享链接中提取纯净参数的解码技巧

很多时候服务商在后台提供的是一串形如 ss://Y2hhY2hhMjAt...#香港专线 的单节点链接。很多小白不知道如何从中提取参数。其实，ss:// 后面的那一长串乱码仅仅是标准 Base64 编码字符串。只需打开电脑浏览器访问任意在线 Base64 解码工具（或使用本地终端命令行），将该字符串解码展开，便会立刻露出其庐山真面目：格式通常为 method:password@server:port，各项核心参数瞬间一目了然，直接对照填入即可。

## 三、手工编写标准 config.json 文件的语法规范与避坑

对于需要直接导入 JSON 文件的设备，可新建一个纯文本文件命名为 config.json。标准文件结构必须遵循严格的 JSON 语法规范（不能有多余逗号、字符必须全英文字符）：包含 server、server_port、local_address（通常填 127.0.0.1）、local_port（本地监听端口如 1080）、password、timeout（通常 300）以及 method 字段。编辑完成后保存并载入设备后台，随后启动服务即可实现老树发新芽的稳定联网。

## 常见疑问解答

### 手动输入完所有参数后保存，客户端显示连接成功，但打开网页直接报 500 错误？

80% 的原因在于加密方式（Method）选择错误，或者密码字符串前后不小心复制粘贴了看不见的隐形空格。请务必检查加密算法拼写是否与服务商提供的字符大小写完全一致。

### 手工配置的单节点，以后服务商更换了节点服务器 IP 会自动同步更新吗？

不会。手动配置属于静态硬编码设置，一旦服务商调整了后端机房 IP 或重置了密码，您必须再次手动获取最新参数并进入配置重新修改；长期使用依然建议优先挑选支持动态订阅的设备环境。
